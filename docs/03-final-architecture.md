## 2. Data models

Internal dataclasses (frozen, standard library; implemented ones as in `models.py`):
- S1: `Atom(raw_start, raw_end, text, kind, char_start, char_end, container_id, path)`,
  `Paragraph(id, element_id, atoms, text, barriers, skip_reason)` (`annotatable` is a property),
  `Token(start, end, text)`, `Word(index, start, end, text)`
- S2: `Annotation(paragraph_id, start, end, category, correction, reason=None)` — a resolved span in code points;
  `Rejection(annotation, code, detail)`; `Insertion(offset, order, data, paragraph_id)` (order 0 = closing tag first);
  `AnnotationOutcome(ok, output, applied, rolled_back, rejected, failures, rounds)` — `output` is None unless it
  verified. `RenderResult` is defined but unused (open item).
- S3 (all frozen; the planned `ResolvedSpan` was replaced by `ResolvedFinding`):
  - Pydantic contract: `Finding(original, before, after, word_start, word_end, correction, type, reason)` (strict,
    frozen, no extra keys) and `FindingList(findings ≤ 30)` (schema export for S4; the resolver validates items one
    by one).
  - `CheckedFinding(index, original, before, after, word_start, word_end, correction, category, reason,
    original_stripped)` — a validated finding without Pydantic; `FindingRejection(paragraph_id, finding_index,
    code, detail)` — `finding_index` None = whole paragraph; `ResolvedFinding(finding_index, annotation,
    match_mode, hint_drift)`; `ResolutionResult(paragraph_id, raw_count, resolved, rejections)`;
    `GridWord(index, start, end, text)`.
  - Quotation: `QuoteMark(offset, char, family, role)`, `ProtectedRange(start, end, open_start, open_end, origin)`,
    `QuoteAnalysis(paragraph_id, marks, ranges, unsafe_reason, inherited_from)`.
  - Trace: `TraceEntry(paragraph_id, finding_index, status, code)` (S3.1 contract, unchanged) and
    `TraceRecord(paragraph_id, finding_index, status, code, match_mode, start, end, hint_drift, detail)` (S3.6
    audit record; `TraceRecord.entry` returns the exact `TraceEntry`) — see §3.4.
  - Enums: `MatchMode` (exact, whitespace_gap, nfc), `QuoteFamily`, `QuoteRole`, `RangeOrigin`, `TraceStatus`
    (APPLIED, REJECTED_S3, REJECTED_S2, ROLLED_BACK, DOCUMENT_FAILED); 9 S3 `RejectCode` members appended after the
    11 S2 codes (S2 codes unchanged).
- S4 result and record types live in `llm.py`, not `models.py` (04, S4.1 implementation notes):
  `ProofreadResult(payload, failure, usage, latency_ms, attempts, request_id, stop_reason)` and the text-free `CallRecord`.

## 3. Finding contract & resolver

```json
{"findings": [{
  "original": "recieve",
  "before": "Our team will",
  "after": "the final report",
  "word_start": 3, "word_end": 3,
  "correction": "receive",
  "type": "spelling",
  "reason": "Misspelling of 'receive'"
}]}
```
Strict JSON schema (`additionalProperties: false`), `type` ∈ {grammar, spelling, punctuation, capitalization, clarity, styleguide}, ≤ 30 findings, `original` 1–300 chars, `correction` 0–300, `reason` 1–200 (required on all).
`before`/`after`: verbatim **uncorrected** source text, ≤ 4 words, empty only at a paragraph edge. Word indices are hints.

For the paragraph `Our team will recieve the final report on Monday.` the user message is the paragraph text in a
delimited data block + `WORDS: 0:Our 1:team 2:will 3:recieve 4:the …` (whitespace-separated words).

Why anchors instead of ±1: proximity is not evidence; anchors are verifiable text, need no counting, and fail closed (a misquoted original with real anchors from elsewhere → ANCHOR_MISMATCH).

**Implemented in S3 (`resolver.py`, `quotes.py`; all T).** Word indices are **0-based and inclusive** into the
**barrier-aware word grid** `resolver.word_grid(paragraph)`: `str.split()` words of each nested-`<p>`-delimited
segment, numbered continuously; a barrier always ends a word (U2). S4 must present exactly this grid (and mark
barriers without presenting them as text).

### 3.1 Processing order (per paragraph; deterministic)

| Step | Check | Rejection (scope) |
|---|---|---|
| 1 | paragraph eligibility (`paragraph_rejection`) | non-int id → `ResolverInputError` (caller error, never stored); negative → INVALID_FIELD; unknown id or skip reason → PARA_NOT_ANNOTATABLE (whole paragraph) |
| 2 | envelope: a dict whose `findings` value is a list | SCHEMA_INVALID (whole paragraph) |
| 3 | **raw** findings count > 30, before any item is validated | TOO_MANY_FINDINGS (whole paragraph) |
| 4 | no other top-level keys | SCHEMA_INVALID (whole paragraph) |
| 5 | each item validated alone (strict Pydantic `Finding`); others continue | INVALID_FIELD (that item) |
| 6 | strip edge whitespace from `original` (flagged) | — |
| 7 | span cap: > 6 words, clarity > 20 | SPAN_TOO_LONG |
| 8 | matching tiers, anchors, exact word tie-break, barriers (3.2) | NOT_FOUND / ANCHOR_MISMATCH / AMBIGUOUS / CROSSES_PARAGRAPH |
| 9 | quotation span check (02 §6.4) | TOUCHES_QUOTATION / IN_QUOTATION |
| 10 | quotation delimiters in the correction (02 §6.5), then canonical no-op (`NFC(correction) == NFC(span)`) | QUOTATION_IN_CORRECTION, then INVALID_FIELD |
| 11 | `Annotation(...)` with `reason` for **every** category (decision I) → `annotation.annotate` (S2: span safety, disjoint-only overlap, render, verify, rollback) | S2 codes (SPLITS_ATOMIC, CROSSES_ELEMENT, IN_CDATA, OVERLAP, CONFLICT, VERIFY_FAILED, …) |

Rejection details name fields, rules and counts only — never document or model text.

### 3.2 Matching (decisions A, C, D; D9)

- Tiers, cumulative by construction: **T1 exact** ⊆ **T2 whitespace gap** (every whitespace run collapsed to one
  space on both sides; no zero-width gaps) ⊆ **T3 NFC** (each cluster NFC-normalised, T2 whitespace rule). Every
  candidate starts and ends on a cluster-aware fine-token boundary (segment-aware), so substrings inside words,
  partial combining sequences and partial ZWJ emoji never match.
- **Fall-through (decision A):** tiers are evaluated in order; the first tier with an anchor-valid candidate
  decides. A tier whose candidates all fail their anchors does not stop the search. After all tiers:
  ANCHOR_MISMATCH if any occurrence existed, else NOT_FOUND.
- **Anchors are authoritative:** compared after edge stripping, whitespace collapsing and per-cluster NFC (quote
  marks stay exact: a straight `"` never matches `“`); the anchor's far end must lie on a fine-token boundary; an
  empty anchor is valid only at the paragraph edge or a barrier; anchors never cross a barrier (decision C).
- **Word hints:** one anchor-valid candidate → accepted (`hint_drift` recorded if the hint differs; informational,
  never a rejection). Several → the one whose (word_start, word_end) exactly equals the hint, else AMBIGUOUS. **No
  fuzzy matching, no ±1 / nearest fallback.**
- A chosen span containing a barrier → CROSSES_PARAGRAPH. A correction canonically equal to the span → INVALID_FIELD
  (decision D). Missing punctuation (AC-24, decision H, an implementation interpretation) is a correction of a
  non-empty span (`However` → `However,`); empty originals are invalid.

### 3.3 Entry points and API safety

| Function | Use |
|---|---|
| `resolve_document(scan, payloads)` | **Recommended production entry point.** Computes `quotes.analyse_document(scan)` once (nested propagation included) and applies quotation protection to every paragraph; it has no switch to turn protection off. Results sorted by paragraph id. |
| `resolve_paragraph(paragraph, payload, quotes)` | One paragraph, steps 1–10; `quotes` is required (no default) and must belong to that paragraph. |
| `annotations(results)` | The annotations to pass unchanged to `annotation.annotate`. |
| `trace(results, outcome)` | One `TraceRecord` per raw finding (3.4). |
| `paragraph_rejection`, `find_paragraph`, `parse_findings`, `word_grid` | Building blocks (steps 1–7, U2). `find_paragraph` uses the position verified against `Paragraph.id`, else the id field. |
| `resolve_findings(paragraph, findings, *, quotes=None)`, `resolve_finding` | **Lower-level building blocks.** With `quotes=None` (default, legacy S3.5 behaviour) they apply **no quotation protection**; use only in tests or with an analysis from `analyse_document`. |
| `quotes.classify`, `analyse_text`, `analyse_paragraph`, `analyse_document`, `nested_barriers`, `span_verdict`, `is_quote_character` | Quotation analysis (02 §6). |

Regression tests prove the production path cannot bypass quotation checks (signatures, a spy on every resolution
call, end-to-end rejection in top-level, inherited nested and guarded paragraphs, and two "bypass" mutants killed).
S3.4 interface deviation (approved): step 1 is the separate `paragraph_rejection(scan, paragraph_id)` because the
approved `parse_findings(paragraph_id, payload)` signature has no access to the scan.

### 3.4 Traceability: TraceEntry and TraceRecord

- `TraceEntry(paragraph_id, finding_index, status, code)` is the approved S3.1 contract and is unchanged.
- `TraceRecord` (S3.6, additive) is the audit record returned by `trace()`: the TraceEntry core plus `match_mode`,
  `start`, `end`, `hint_drift` (set only for findings that resolved to a span) and `detail` (the S3 rejection detail;
  empty for S2 outcomes, whose messages may quote document text). `TraceRecord.entry` returns the exact
  `TraceEntry`, so code written against the S3.1 contract keeps working.
- One record per raw finding, sorted by (paragraph id, raw index) and independent of the order of the results.
  Whole-paragraph rejections expand to every raw index, or to a single record with index None when no findings list
  was readable (or it was empty).
- Status of a resolved finding: rejected by S2 in prepare → REJECTED_S2 (S2 code kept); rolled back after
  verification → ROLLED_BACK (VERIFY_FAILED); `annotate()` failed closed → DOCUMENT_FAILED; otherwise it must be in
  `outcome.applied` → APPLIED. S3 rejections → REJECTED_S3. `trace()` raises ValueError if the outcome does not
  belong to the results.

### 3.5 Invariants

- Every raw finding has exactly one outcome and one trace record; its outcome depends only on that finding (never on
  response order or on other findings). *(tests and properties)*
- The resolver never computes byte offsets; every byte-level guarantee (atomic references, CDATA, D4 off, G1,
  V1–V6, rollback) stays in S1/S2. *(by design: `resolver.py` does not import `xml_source` or use any byte mapping;
  not a separate test)*
- Every finding resolved through `resolve_document` lies outside, and not adjacent to, document-level protected
  quotation content. *(property test and no-bypass regression tests)*
- **D15 stays disabled:** S3 never selects, merges or discards competing findings; S2's `select_disjoint` rejects
  all overlapping / conflicting ones (identical duplicates collapse) and each stays traceable. *(trace tests)*

### 3.6 Example (the contract example above)

Paragraph `Our team will recieve the final report on Monday.`; finding `original "recieve"`, `before "Our team will"`,
`after "the final report"`, hint (3, 3): T1 finds one aligned occurrence at code points [14, 21); both anchors hold;
no quotation marks; the correction differs → `Annotation(pid, 14, 21, spelling, "receive", "Misspelling of
'receive'")` → applied by `annotate` → `TraceRecord(pid, 0, APPLIED, None, exact, 14, 21, False, "")`.

## 5. Processing flow

```
argv → RunConfig
  → encoding.check(bytes)            (fatal → exit 1/2, no output, no API call)
  → style_guide.load(docx) + locale rule selection (D8) → system prompt (byte-stable per run; cached only if D13 caching is enabled)
  → xml_source.scan → paragraphs (ownership, barriers, annotatable flags)
  → for each annotatable non-empty paragraph (bounded concurrency; --cache is refused until caching exists, S4.6):
        word grid → llm.proofread → raw response (payload)                                   (S4)
  → resolver.resolve_document(scan, payloads)   (S3: quotes.analyse_document once; steps 1–10 of §3.1 per paragraph)
  → annotation.annotate(data, scan, resolver.annotations(results)): prepare → render (single pass, from the
        original bytes) → verify (G1, V1–V6)
        failing paragraph → roll back, re-render from the original; document-level failure → write nothing, exit 1
  → resolver.trace(results, outcome) → one TraceRecord per raw finding (logged as counts only, S4.7)
  → atomic write <stem>.corrected.xml → metrics summary → exit code                (S4.7, §5.2)
```

### 5.1 Pipeline orchestration (S4.6, implemented in `pipeline.py`)

`pipeline.run(data, config, proofreader, guide) -> PipelineResult` reads no files or environment and builds no
client; the CLI (S4.7) loads the guide, chooses Fake / Replay / Anthropic, writes the output and maps the exit code.
`PipelineResult` holds the verified output bytes and text-free records: `call_records` (one `CallRecord` per
paragraph sent or size-guarded, sorted by paragraph id), `trace`, `rolled_back`, `degraded`, `usage`,
`requests_sent`, `stage_ms`.

1. `config.cache` true → `UsageError` (exit 2) before anything else: caching is not implemented (Q3).
2. `xml_source.scan` (encoding check included); fatal input errors are raised before any call.
3. Eligibility in paragraph-id order: a skip reason or whitespace-only text → never sent, no record (AC-11, AC-25);
   over 5,000 characters or 50 words → not sent, `NOT_CALLED` / `REQUEST_TOO_LARGE`, paragraph unchanged.
   A paragraph with non-whitespace text skipped as `PARA_UNMAPPABLE` or `DOCUMENT_UNVERIFIABLE` (X10 / C2: it
   could not be proofread safely) is listed in `PipelineResult.not_proofread` as (paragraph id, skip reason) and
   makes the run `degraded` (exit 3; S4.8c fix). Its bytes pass through unchanged and nothing is fetched.
   `PARA_HAS_ERROR`, `EMPTY` and `CDATA_ONLY` stay intentional skips (no effect on the exit code).
4. Before any request: `--max-calls` (counted in paragraphs to be sent; one paragraph may use up to 6 HTTP
   requests through retries) → `UsageError`; a `ReplayProofreader` missing any request fingerprint →
   `ReplayMissError` (exit 1). Error messages give counts only.
5. Bounded fan-out: a thread pool of `min(concurrency, requests)` workers (AC-28); results keyed by paragraph id,
   never by completion order (AC-20).
6. Only successful results (`failure is None`) reach the resolver; failed, refused, truncated or schema-invalid
   payloads never do (Q1). Their paragraphs pass through unchanged; the run is `degraded` (exit 3 in S4.7).
7. No applicable guide text (empty or whitespace only) → every resolved `styleguide` finding is rejected before
   annotation, traced as `REJECTED_S3` / `INVALID_FIELD` with a fixed detail (Q2; no new code or schema).
8. `annotation.annotate`; a document-level failure raises `DocumentVerificationError` (a `RunFatalError`, exit 1,
   message with an issue count only): no partial output is ever returned (Q5). A rollback marks the run `degraded`.

**Start gate (synchronisation guarantee).** The only provider invocation is inside the worker function, after
`_StartGate.try_start(paragraph_id)` returns True. `try_start` ("queued → started") and `stop` ("→ stopped") run
under one lock, so they are totally ordered: a call is started only if the gate was not stopped at that instant;
after `stop` no call is ever started (`started` equals the snapshot `started_at_stop`). A call started before the
stop may still be entering the provider and is allowed to finish. The gate is stopped by every failing call (any
`BaseException`, including a non-`ProofreadResult` return value) before its worker takes more work, and by any
`BaseException` in the calling thread (e.g. `KeyboardInterrupt`). A deterministic reproduction showed that the
earlier unsynchronised check-then-call design let a call enter the provider after the stop.

**Cancellation and error selection (Q4).** After the first observed failure, queued futures are cancelled, running
calls finish, and `shutdown(wait=True, cancel_futures=True)` leaves no worker thread. Of the failures observed by
then, a non-`Exception` `BaseException` takes precedence; otherwise the lowest paragraph id is raised. The observed
set depends on timing, so the choice is deterministic only for a given set of observed failures.

### 5.2 Command line and publication (S4.7, implemented in `cli.py` and `metrics.py`)

Entry point: `python -m proofreader INPUT --lang TAG --style-guide GUIDE.docx [options]` (`__main__.py` calls
`cli.main()`, which returns the exit code). Options: `--replay FILE` or `--record FILE` (mutually exclusive),
`--model`, `--concurrency` (1–64, default 8), `--timeout` (1–600 s, default 60), `--max-calls` (1–100,000, default
200), `--cache` (refused: not implemented), `--force`, `--base-url`, `--allow-custom-base-url`, `--heap-metrics` /
`--no-heap-metrics`, `--log-level` (DEBUG, INFO, WARNING, ERROR; default INFO), `--log-file`, `--metrics-json`.
Precedence: CLI > process environment > `./.env` > defaults (04, "S4 CLI and configuration").

Order of work: parse → logging → `plan_artifacts` → read input → load style guide, manifest and locale selection →
choose the client (Replay with `--replay`; otherwise Anthropic, which needs the key; tests inject a client through
the keyword-only `proofreader_factory` parameter of `main()`, which has no command-line flag) → `pipeline.run` (the
client is always closed afterwards) → publication. Every usage or fatal error before `pipeline.run` happens before
any API call and before any file is written.

**Artifact paths (checked by `plan_artifacts` before any API call).** The corrected XML is `<stem>.corrected.xml`
next to the input; only the last suffix is replaced (`x.xml`, `x` → `x.corrected.xml`; `a.b.xml` →
`a.b.corrected.xml`). No artifact (corrected XML, recording, metrics JSON, log file) may be the input or an alias of
it (same file through a symlink, hard link or a case variant on a case-insensitive filesystem), even with `--force`;
no two artifacts may be the same file; an existing target is refused unless `--force` (exit 2); a recording name
must end with `.recording.json` (exit 2); every destination directory must accept a new file (else exit 1).

**Atomic publication.** Every artifact is written to a temporary file in its destination directory, fsynced, then
published exclusively (Windows `os.rename`, elsewhere `os.link`) or, with `--force`, by `os.replace`; on failure
nothing is published and the temporary file is removed. The input is never overwritten, even with `--force`. The
recording is published by the existing `RecordingWriter` (exclusive publication through `os.link`).

**Publication order and failure semantics (approved).** 1. corrected XML, 2. recording, 3. metrics JSON, 4. log file
(the log is buffered in memory and written last). If the corrected XML cannot be published, neither the recording nor
the metrics JSON is written (the log file still is). If an auxiliary artifact fails after the XML was published, the
XML is never deleted or rolled back, the remaining auxiliary artifacts are still attempted, stderr states that the
corrected XML was written, and the exit code is 3. The recording is written after every completed pipeline run,
degraded runs included, and never after a fatal pipeline failure; an existing recording target is refused before any
API call unless `--force`. After a fatal error only the log file (if requested) is published.

**Exit codes.** 0 success; 3 corrected XML written but degraded (a paragraph passed through, was size-guarded, was
rolled back, or could not be proofread because it was unmappable or the document was unverifiable) or an auxiliary
artifact failed; 1 fatal (no corrected XML), including an internal error, which is
reported by exception type only; 2 usage or unsupported input (no corrected XML); 130 interrupted
(`KeyboardInterrupt`; the message says whether the corrected XML had already been written).

**Logging.** A private `proofreader` logger writes `LEVEL message` lines (non-ASCII escaped) to stderr and, with
`--log-file`, to the buffered log file. After the corrected XML is published, one runtime summary line (S4.8e
B21): `run time T s (stage times, pipeline stages in brackets); peak heap X MiB|n/a; peak process memory Y MiB|n/a`
(not logged when no corrected XML was produced). Per paragraph: id, status, failure class, attempts, latency and request id;
a WARNING `paragraph N: not proofread (REASON)` for every not-proofread paragraph (id and reason only)
(passthroughs at WARNING); findings by status and code; rolled-back paragraph ids; request and token totals. No
document text, corrections, prompts or style-guide content is logged at any level, DEBUG included; an internal
error is logged by type only, with code frames (no values) at DEBUG. The API key is replaced by `***` in every line.
The `anthropic`, `anthropic._base_client`, `httpx2`, `httpcore2`, `httpx` and `httpcore` loggers are pinned to
WARNING for the run (again after the SDK is imported) and restored afterwards.

**Metrics (`--metrics-json`).** Total and per-stage time (plus the pipeline's own stages), per-paragraph latency
(min, median, max, per paragraph), paragraphs by status and failure class, rolled-back paragraphs, not-proofread
paragraphs by skip reason, requests sent,
tokens (input, output, cache write, cache read), findings by status and code, auxiliary failures, and memory reported
separately: Python heap peak from `tracemalloc` (`"n/a"` when heap tracing is off, even if something else traces)
and process peak memory (Windows peak working set through `K32GetProcessMemoryInfo`, POSIX `getrusage`, else
`"n/a"`; no psutil). File names only, never directories; no text and no key. `exit_code` is the code at the time the
metrics were written.

## 6. Error handling & rollback

| Level | Examples | Action | Exit |
|---|---|---|---|
| Usage / unsupported | bad args, malformed `--lang`, unsupported encoding | message, no output | 2 |
| Fatal input | malformed XML, invalid bytes, unreadable input/DOCX, missing API key | message, no output | 1 |
| Paragraph | API failure after retries, schema failure after repair retry, refusal, max_tokens | paragraph passthrough | 3 (output written) |
| Not proofread (S4.8c) | paragraph text skipped as `PARA_UNMAPPABLE` (markup-bearing or skipped entity, failed self-check) or `DOCUMENT_UNVERIFIABLE` (ElementTree cross-check impossible, e.g. external DTD with undeclared entities) | paragraph passthrough; WARNING with id and reason; nothing fetched | 3 (output written) |
| Finding | any rejection code | dropped + logged | 0 |
| Verification | paragraph fails V1–V6/G1 | paragraph rolled back | 3 |
| Internal bug | document fails after rollback | nothing written | 1 |
| Existing artifact (S4.7) | corrected XML, recording, metrics or log target exists without `--force`; artifact is the input or an alias; two artifacts collide | message, nothing written, no API call | 2 |
| Auxiliary artifact (S4.7) | recording, metrics JSON or log file cannot be written after the corrected XML was published | XML kept; other artifacts still attempted | 3 |
| Interrupt (S4.7) | `KeyboardInterrupt` | message says whether the corrected XML was written | 130 |

## 7. Performance & security

Performance: skip empty/unannotatable paragraphs; optional prompt caching (D13, after verification); bounded concurrency (default 8); effort low; `max_tokens` ≈ 8k non-streaming; 60 s timeout; linear Python processing.

Security: API key via env/.env only, never logged, `.env` gitignored; expat never fetches external entities, amplification protection, input size cap; document text in delimited data block + strict schema (worst case: wrong but validated findings); all attribute values escaped; README discloses that text is sent to the provider; output never overwrites input; atomic writes; no document text, corrections, prompts or style-guide content in logs at any level (S4.7, D2).
